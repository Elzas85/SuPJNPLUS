# SuPJN+ 1.3.7: revisión del código con ESLint

Fecha: 25 de septiembre de 2026
Versión anterior: 1.3.6 (del mismo día)
Banco de pruebas: 191 pruebas con resultado satisfactorio y 0 fallidas (las
mismas 191 de la 1.3.6).
Analizador propio: 0 avisos. ESLint: 0 errores.
Textos de pantalla: sin cambios.

Esta versión no agrega ni modifica ninguna función. Constituye la revisión de
fondo del código solicitada por el autor: sin premura, con la mejor herramienta
disponible, para que el código quede correcto y ordenado.

## 1. La herramienta

Hasta esta fecha, el código se revisaba con un analizador propio, escrito en
Python porque el instalador de paquetes de este entorno responde 403. El 25 de
septiembre se constató que **ESLint 10 ya estaba instalado** en el entorno,
aunque no sea posible instalar nada nuevo. Es el analizador de referencia para
JavaScript, y se lo aplicó a las dos aplicaciones.

La configuración quedó en el repositorio, en `eslint.config.js`, con las 64
reglas recomendadas de ESLint más las de calidad y orden relevantes en un archivo
único de nueve mil renglones. Se ejecuta desde la carpeta del repositorio con
`npx eslint supjn-plus.user.js`. Requiere ESLint 9 o posterior.

## 2. Hallazgos y correcciones

Sobre la 1.3.6: **371 observaciones**. Ninguna correspondía a un error que
estuviera produciendo fallas en ese momento; varias eran de las que pueden
producirlas en el futuro.

| Observación | Cantidad | Medida adoptada |
|---|---|---|
| Sangría distinta de la correspondiente | 281 renglones | Se alineó todo con la herramienta. Se comprobó que el único cambio fueran los espacios iniciales de cada renglón. |
| Parámetro con el mismo nombre que una función general del programa | 13 funciones | Las funciones de lectura recibían un parámetro llamado `avisar`, con el mismo nombre que la función que muestra los carteles, y la ocultaban. Pasó a denominarse `informar`. |
| Variable local con el mismo nombre que una función general | 20 lugares | `clave`, `q`, `opciones`, `ventana`, `ficha`: cada una ocultaba la función del mismo nombre. Se les asignó un nombre propio. |
| Una función auxiliar escrita dos veces | 1 | `dos` (completa con cero a la izquierda) estaba definida de forma idéntica fuera y dentro de una función. Se conservó la definición externa. |
| Valor inicial que nunca se lee | 8 | `let v = null; try { v = … } catch { v = null }`: el primer `null` no se leía nunca. |
| Parámetro sin uso | 1 | El manejador de los botones recibía el evento y no lo utilizaba. |
| Función que en algunos casos devolvía un valor y en otros no | 1 | Ahora devuelve siempre un valor. |
| Error nuevo que descartaba el original | 5 | Cuando se captura un error y se lanza otro con un mensaje más claro, el original se transmite dentro de él (`cause`). No cambia ningún mensaje. |
| Función marcada como asíncrona sin serlo | 3 | Se quitó la marca y se explicitó el valor que devuelven. |
| Variable declarada como modificable y nunca modificada | 1 | `CFG` pasa a constante. Sus campos siguen pudiendo modificarse del mismo modo. |
| Escape innecesario en una expresión regular | 1 | `["\']` pasa a `["']`. Reconoce los mismos caracteres. |
| Un renglón de 215 caracteres | 1 | Se dividió en dos. |

Todo se realizó con cambios de nombre acotados a cada función y sin modificar
textos ni comentarios, y luego se comprobó:

- Banco de pruebas: **191 con resultado satisfactorio**, las mismas de la 1.3.6.
- Comparación de textos con la 1.3.6: **ningún texto cambió**.
- Analizador propio: 0 avisos. ESLint: **0 errores**.

## 3. Tarea pendiente: las funciones extensas

ESLint también mide el tamaño y la complejidad de cada función, aspecto que no
se corrigió en esta versión porque no constituye una corrección: es la división
en funciones breves solicitada por el autor el 23 de septiembre, y es
exactamente el tipo de trabajo que originó los errores de esos días en EJE+.
Conviene realizarla por separado, de una función por vez, con el banco, los dos
analizadores y la comparación de textos como control.

El orden propuesto es el siguiente: primero, las que no interactúan con el PJN
ni con los datos guardados (`accionDeBoton`, `alClic`, `escuchasDeLosCampos`,
`escuchasDeLaVentana`, `celdaBandejaHTML`); después, las de lectura

`puenteEnMarco`, `atender`); y al final, las dos que actúan sobre el PJN
(`cedulaEnNotif` y `pasoNotaInterno`), que requieren pruebas nuevas antes de
modificarlas.
